# files-view acceptance spec

All items must pass. Run from the worktree root. Env for every Postgres item:
`PATH=/opt/homebrew/opt/postgresql@16/bin:$PATH LC_ALL=en_US.UTF-8 NODE_AUTH_TOKEN=x`,
`DATABASE_URL=postgres://postgres@127.0.0.1:<port>/postgres`, a `mktemp -d` data dir, removed with `rm -rf`
when done. The verifier runs each command and records exit code and output tail. A claim without a
command that exited 0 does not count. Builders do not edit this file (lead owns it).

## Data model (fixed; graph-store source is not altered)

- File: graph node `kind: "document"`; metadata only in `props`: `owner`, `zone`, `mime`, `size`,
  `modified`, `folder`. No body, preview or snippet keys (graph-store rejects them; ADR 0004).
- Cluster: graph node `kind: "project"` with props `cluster.type` (`place|people|topic`), `cluster.why`
  (one metadata sentence, e.g. "Same folder /finance/q3"), optional `cluster.parent` (cluster id).
- Membership: edge `belongs-to` from document id to cluster id. Tree: `cluster.parent`.
- files-view may add read-side indexes via a `migrate(pool)` it owns (`CREATE INDEX IF NOT EXISTS`, partial
  on current rows `valid_to IS NULL`). It must not edit graph-store.

## Items

1. Package shape: `modules/files-view` has `package.json` (`@anvesx/files-view`), `tsconfig*.json`,
   `README.md`, `src/README.md`, `tests/README.md`. Proof: `pnpm install --no-frozen-lockfile && pnpm
   structure` exits 0 and its package count includes files-view.
2. Typecheck and build: `pnpm --filter @anvesx/files-view typecheck && pnpm --filter @anvesx/files-view
   build` exit 0.
3. Tests on real Postgres: `pnpm --filter @anvesx/files-view test` (output saved to a file, hard cap 15 min, run to the end with a Test Files summary) exits 0, throwaway Postgres 16 started
   by test setup, zero skipped tests, zero `it.todo`.
4. Coverage: the same run enforces lines, branches, functions >= 90 and prints the table.
5. Fake guard: `pnpm guard:fakes` exits 0 with no new `fake-baseline.json` entries. No `vi.mock`, `vi.fn`
   standing in for pg, HTTP or OIDC, and no pg-mem or pglite, anywhere in the package.
6. Lint and size: `rm -rf modules/files-view/coverage && pnpm exec biome check modules/files-view` exits 0 (repo-wide `pnpm lint` is informational only; foreign-package errors are out of scope); files <= 80 lines, <= 5 per folder, README in each src/tests folder
   (enforced by item 1).
7. Self-check: `bash ~/.claude/skills/l8-code/scripts/selfcheck.sh modules/files-view` exits 0.
8. Dependency rules: `pnpm deps` AND `pnpm exec depcruise modules/files-view --config .dependency-cruiser.cjs` exit 0 (`pnpm deps` does not scan modules/; imports only core-types, graph-store, visibility, design-system;
   nothing from apps or services).
9. Listing correctness: test seeds 3 tenants, 3 viewers, 500 files, 40 clusters over 3 levels. Listing
   returns exactly the gate-approved files, each with up to 3 cluster paths (root > ... > leaf) and each
   cluster's `why`. Asserted by exact id sets.
   A cached cluster tree must re-apply the gate on every hit (revoked can-read edge or tombstoned file must vanish at once).
10. Permission gate: every read path (list, search, detail, cluster tree, cluster members, counts) calls
    `openGate(...).approve`. Tests prove: other-tenant file never appears; file in a zone the viewer lacks
    never appears; file with no `can-read` for the viewer never appears; recheck returning false or
    throwing hides the file; a hidden file's id on the detail route returns 404 identical to a missing id;
    cluster counts exclude hidden files; `readers` shown only to owner or admin. A test greps src and
    fails if any route reads the store without the gate.
11. Keyset pagination: opaque cursor (base64url of sort keys plus id); `rg -n "OFFSET"
    modules/files-view/src` returns nothing. Test pages 5,000 rows in every sort order: union of pages
    equals the full set, no duplicates, no gaps, stable when rows are inserted between fetches. A tampered
    cursor returns 400, never 500.
12. Search and filter: title substring (uses `nodes_title_trgm`), filter by source, mime, owner, cluster,
    modified range (compared as parsed instants, never text: `to` inclusive of its whole second, `from == to` matches that second, `+05:30` equals the same UTC instant); sort by modified, title, size. Gate filtering happens before return and pages are not
    short while approved rows remain (bounded over-fetch loop, tested with a viewer who sees 1 in 50 rows).
13. Scale and index use: seed 100,000 files and 2,000 clusters by bulk insert. For list, search,
    cluster-members and cluster-tree run 200 sequential requests each: p95 <= 150 ms for the DB query and
    <= 300 ms TTFB over HTTP. A test runs `EXPLAIN (FORMAT JSON)` on each hot query and asserts no `Seq
    Scan` on `nodes` or `edges` and that the expected index name appears. It prints the p50/p95 table and
    plan node types. Must use the module's real `migrate`, real queries and real HTTP (no test-local indexes or SQL).
    Cold first `/clusters` for the largest-visibility viewer is timed and printed separately: <= 300 ms, or the
    measured number is documented in README as a known limit. One shared 100k world is seeded once in
    `globalSetup`; whole scale suite under 8 min; setup failure throws, a skipped test fails the gate.
14. HTTP screen: a real Hono server (`@hono/node-server`, ephemeral port) serves `GET /files`,
    `/files/:id`, `/clusters`, `/clusters/:id`. Auth verifies tokens against a real local OIDC/JWKS HTTP
    endpoint (`jose`, or `oidc-provider`), no header-trust shortcut. No or bad token returns 401 and renders
    no data. Responses carry a strict CSP and `no-store`; titles are HTML-escaped (test with `<script>`).
15. Rendered content: HTML has a table row per file (title, source, owner, modified, size, cluster path
    chips), the cluster `why` text, an empty state, a next-page link with the cursor, and a removed state
    when the recheck says the source no longer allows access.
16. Light and dark: HTML uses design-system tokens, supports `prefers-color-scheme` both ways, and a test
    asserts every foreground/background token pair used meets WCAG AA (culori).
17. Browser and a11y: Playwright (Chromium; lives in `tests/integration/browser` or `tests/e2e`, and must run and pass inside item 3's command or be run explicitly) loads the screen in both color schemes and
    runs `@axe-core/playwright` with zero violations. Keyboard test: Tab reaches skip link, search,
    filters, rows, next page; Enter opens detail; focus is visible. Screenshots go to an uncommitted
    folder and the path is printed. If Playwright or axe cannot install, the lane reports it, and the
    fallback is `axe-core` in `jsdom` on the served HTML with the same zero-violation threshold.
18. Injection and limits: live source rechecks capped at 1 per distinct file id per request (`GET /files?limit=100` makes <= 200 rechecks, tested with a counter); SQL uses parameters only (test `'; DROP TABLE nodes;--` in search, filter, cursor);
    page size capped at 100; search length capped; unknown sort or filter returns 400.
19. Standalone: `src/index.ts` exports `createFilesView({ pool, gate, auth })` returning a Hono app. README
    documents wiring, env vars, routes, limits and what is not covered. Runs with only Postgres and an OIDC
    provider; no dependency on apps/connections.
20. Honest evidence: `todo/EVIDENCE.md`, written by the verifier, lists command, exit code and output tail
    for items 1 to 19. Anything not executed is NOT RUN and fails the gate.

## Gate (verifier)

Runs items 1 to 19 in order in the worktree on its own Postgres port; builder claims are never proof. PASS
only if every item exits 0 and every threshold holds. Any NOT RUN, skipped test, lowered threshold, edited
root config or edited foreign package contract test fails the whole swarm.
